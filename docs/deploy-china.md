# 国内部署 / Deploying for mainland China

原型是纯静态文件，**没有任何境外依赖**，因此国内部署只需要一个对象存储 + CDN。真实后端上线后再考虑服务器与备案。

## 1. 静态原型（v0.1）

### 方案 A：腾讯云 COS + CDN

1. 创建 COS 存储桶（公有读），开启「静态网站」；
2. 上传 `web/` 目录内容到根路径（`index.html` 在根）；
3. 绑定 CDN 加速域名（需已备案域名），开启 HTTPS；
4. 因为使用 hash 路由（`#/careers`），**不需要**配置 404 重写。

### 方案 B：阿里云 OSS + CDN

同上：Bucket 静态页面托管 → 默认首页 `index.html` → CDN 加速 → HTTPS。

### 方案 C：GitHub Pages（海外）+ 国内镜像

- 海外用户走 GitHub Pages（本仓库 `deploy-pages.yml` 自动部署）；
- 国内用 GitHub Actions 在每次 push 后同步到 COS / OSS（腾讯云 `TencentCloud/cos-action`、阿里云 `ossutil`），密钥放在仓库 Secrets。

### 可选：Gitee 镜像

用 Gitee 的「仓库镜像」功能从 GitHub 同步，方便国内贡献者克隆；Issue / PR 仍以 GitHub 为主。

## 2. 域名与备案

- 使用国内 CDN 加速必须是**已 ICP 备案**的域名；备案主体可以是个人（有限制）或校友会 / 公司主体；
- 若暂时没有备案域名，可以先用云厂商提供的临时域名做内测，或只走海外 Pages。

## 3. 真实后端（v0.2+）

| 组件 | 国内选型 | 备注 |
|---|---|---|
| 服务器 | 腾讯云轻量 / 阿里云 ECS（2C4G 起） | 单体后端足够；Docker 部署 |
| 数据库 | TencentDB / RDS for PostgreSQL | 每日自动备份 |
| 对象存储 | COS / OSS | 头像、SOP 材料、海报 |
| 邮件验证码 | 腾讯云 SES / 阿里云邮件推送 / SendGrid（海外用户） | 发到 yale.edu 的邮件需注意 SPF/DKIM；建议双通道：国内服务发国内、海外服务发海外 |
| 缓存 / 限频 | Redis | 验证码限频 |
| 监控 | 云监控 + Sentry 自托管 | |

### 邮箱验证在国内的坑

- yale.edu 邮箱由 Google Workspace 托管，国内直接访问 Gmail 网页不方便，但**收信本身不受影响**（走邮件协议）；用户可用 Outlook / 网易邮箱大师等客户端；
- 验证码邮件从国内 IP 发出容易被 Google 判为垃圾，务必配置 SPF、DKIM、DMARC，并考虑用海外发信服务发往 yale.edu；
- 提供「魔法链接」+「6 位码」两种方式，客户端不方便点链接时可手输。

## 4. 微信生态衔接（v0.3）

- **绑定而非替代**：邮箱验证仍是唯一信任边界，微信登录只作为绑定后的快捷登录；
- **微信模板消息 / 订阅消息**：活动提醒、任务分配、志愿者确认；需要小程序或服务号主体（校友会主体更合适）；
- **小程序壳**：只做高频场景（活动报名、志愿者、任务反馈），复用后端 API；
- **群通知**：仍靠人工转发；平台生成一键复制的推送文案（沟通模板模块已提供）。

## 5. 合规要点

- 《个人信息保护法》：注册时明示收集目的；提供注销与删除；联系人库属于他人信息，只存业务必需字段并限定学联成员访问；
- 数据出境：若数据库在国内而用户在美国，或反之，评估是否涉及跨境传输；早期可以将主库放在用户主要所在地，另一地只做只读缓存；
- 内容合规：上线评论与发帖前接入敏感词与人工审核。
